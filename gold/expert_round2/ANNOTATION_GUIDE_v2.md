# 第二轮专家标注说明

本说明面向独立专家，用于完成三项标注。三项标注彼此独立，可分开发送与回收。
所有表格以 UTF-8 编码，可直接用 Excel 或 WPS 打开填写，请勿改动列名与行序。

## 任务一：规则对冲突判定（`01_conflict_pairs_round2.csv`，214 行）

### 目的

对已有第一轮裁决的 214 个规则对做**独立盲标**，用于计算标注一致性系数。
第一轮的结论已从表中移除，请勿向他人查询第一轮结果。

### 每行需要填写的三列

**1. 冲突判定**，取值之一：

| 取值 | 含义 |
|---|---|
| 无冲突 | 两条规则可同时履行，或属于同一体系内的具体化、分工、并行义务 |
| 场景依赖 | 是否构成冲突取决于未在规则文本中固定的要件事实，如主体身份、数据规模、数据是否含敏感个人信息 |
| 稳定冲突 | 两条规则对同一行为给出无法同时满足的要求，且该结论不依赖额外事实 |

**2. 处置结论**，取值之一：

| 取值 | 含义 |
|---|---|
| 并存 | 两条规则各自有效，需同时满足；跨法域义务原则上按此处理 |
| 待定 | 规范衔接的官方口径未明，现阶段无法给出确定结论 |
| 左压制右 | 左栏规则排除右栏规则的适用 |
| 右压制左 | 右栏规则排除左栏规则的适用 |

**3. 法理依据**，取值之一：`lex_specialis`、`lex_superior`、`lex_posterior`、`contextual`、`none`。
填 `none` 表示结论不依赖效力优先关系，例如跨法域的并行义务。

### 判定时应遵循的规则

1. **跨法域的义务是累积的**：内地法与香港或澳门法律对同一操作各提要求时，一方不会压制另一方，
   此时应填"无冲突"或"并存"，不得填压制方向。
2. **效力位阶只在同一法域内比较**：不同法域的规则不比较层级高低。
3. **推荐性文件不构成压制依据**：团体标准、推荐性技术指南不进入法源体系，
   不得以"特别法优于一般法"为由压制法律、行政法规或部门规章。
4. **数量门槛要看是否含敏感个人信息**：涉及敏感个人信息的，针对一般个人信息设定的数量豁免不适用。
5. **不臆断未给出的要件事实**：主体身份、数据规模等事实若在行内信息中无法确定，请填"场景依赖"并说明缺哪一项事实。

### 判定结果如何使用

以 214 个规则对为单位计算 Cohen's κ 与三分类的一致性比例；
处置结论与法理依据按同一方式计算。κ 低于 0.6 的类别将提请第三位专家复核。

## 任务二：风险评分（`02_risk_scores.csv`，200 行）

### 目的

为风险识别层提供人工参考值，用于计算风险校准误差。
每行是一条已经过脱敏处理、由合成人群生成的合规查询。

### 需要填写

**风险得分 0–1，保留两位小数**，参照以下锚点：

| 区间 | 参照情形 |
|---|---|
| 0.00–0.30 | 数据以非敏感字段为主，用途明确，接收方位于同一法域 |
| 0.30–0.60 | 含少量敏感字段，或接收方位于另一法域但有成熟便利机制 |
| 0.60–0.85 | 含多类敏感字段且存在组合识别可能，或流向监管口径未明的法域 |
| 0.85–1.00 | 含基因、生物识别等高敏字段且规模较大，或目的地存在明确处罚与安全审查要求 |

评分请同时考虑三点：**字段组合效应**（多个低敏字段关联后的可识别性）、
**操作情境**（用于模型训练高于用于临床诊疗）、**法域差值**（监管强度差异）。

**风险等级**：低 / 中 / 高，作为得分的离散化，用于检查你自己的打分是否自洽。
**标注把握度**：高 / 中 / 低。把握度为"低"的行请在备注中写明原因。

### 结果如何使用

以平均绝对误差衡量模型得分与专家得分的偏差，并以 Spearman 相关衡量排序一致性。

## 任务三：结论效用评分（`03_decision_utility.csv`，120 行）

### 目的

评估系统给出的合规结论是否在法律上成立、在业务上可用。这是决策层唯一的评价来源。

### 需要填写

**法律有效性 1–5**：

| 分值 | 含义 |
|---|---|
| 5 | 结论正确，援引规范完整，未遗漏应适用的强制性要求 |
| 4 | 结论正确，但援引或表述有可改进之处 |
| 3 | 结论大体正确，遗漏了次要要求 |
| 2 | 结论部分错误，遗漏关键义务或误判优先级 |
| 1 | 结论错误，会导致违规操作 |

**业务效用 1–5**：

| 分值 | 含义 |
|---|---|
| 5 | 给出可直接执行的操作路径，成本与风险相称 |
| 4 | 路径可执行，但缺少部分实施细节 |
| 3 | 结论正确但过于笼统，需业务方二次翻译 |
| 2 | 结论过度保守，禁止了本可合法开展的操作 |
| 1 | 结论不可执行 |

**是否过度保守**：填"是"或"否"。凡结论要求采取严于法定最低要求的措施，且未说明理由的，填"是"。

**遗漏的关键规范**与**修改建议**：可留空；若填"法律有效性 ≤ 3"，请尽量写明遗漏的规范。
